Intake view — designed with the Six Minds

Goal: bring N documents in, and know at every moment where each one is on the way to being sources in the vault. Click a frame to open it. Data is measured: the book (972 chunks → 117 sections, 5 m 33 s), the CV (55 → 2, 2.3 s).

The blended design (final) — three states of one screen

final.html — batch + review (use the state switcher bottom-left inside: landing · batch · after publish)

The three Buxton concepts it was blended from

A · task-oriented / minimalist

One line, one verb per file. Fastest to act on; the process and the goal are implicit.

B · contextual / conventional

Upload-manager table + wizard breadcrumb. Zero learning cost; the wizard lies about N files at different steps.

C · immersive / emotional

Headline, batch bar, a ring per file, one bold CTA. Strong appeal; rings do not scale, percentages are unmeasured.

What was taken from each

from Aone row per file, one action per row, grouped by what it needs from you; no chrome that is not information
from Bthe four-step schema everyone recognises (choose → convert → review → done) — but per file as a journey strip, not per batch as a wizard, because files are at different steps at once; the Source type / Folder fields; “Retry”, “Remove”, “Open”
added on revieweach section opens to a rendered preview of the exact content that will be written (real slices from the book in the mock) — the decision is made where the evidence is
from Cthe goal header with a segmented batch bar toward “in the vault”; the single high-contrast CTA; the completion check that pops; the drop zone that is always there for file N+1
placementno new tab — the panel lives inside the Sources view above the folder list; the Sources tab badge counts files that need the user, so the batch can be left and come back to
rejectedpercentages of any kind (Tier 1 progress is elapsed time — spec §9); rings (do not scale past ~8 files); hiding the batch during review (B) — the list stays beside the review pane
