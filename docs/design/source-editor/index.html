bai/source editor — three concepts and the blend

Six Minds of Experience (`.claude/skills/six-minds-design-skill.md`) · live `--bai-*` tokens · same theme, re-arranged only.

design proposal, awaiting green light. Nothing in the React editor has been changed.

The surface, named first: Command / Inspect — one object drilled into, where reading is the job and every other control is peripheral. Not a Monitor (nothing is watched over time), not Decide/Learn (there is no argument to make). That commitment is what rules out cards, tiles and hero compositions before a colour is chosen.
A · minimal
  • the page is the reading surface: no card, no inner scroller
  • 40px bar, three facts, one action per intent — nothing to hunt
  • text-only actions: weight, not boxes, carries hierarchy
  • hides the source's own purpose — 12 claims are one word in the bar
  • the queue action simply disappears once a source is extracted
B · conventional
  • nothing has to be learned — title, tabs, outline, inspector
  • everything about the source is visible at once
  • tabs are the right vocabulary for claims / history / original
  • the text is back inside a card, inside a page inside a scroller
  • 212px rail + 268px inspector take the centre by default
  • reading becomes one of four equal tabs, two of them inert
C · immersive
  • reads like a document: generous measure, nothing else on screen
  • the derived notes arrive as the payoff at the end of the text
  • one 2px progress line is the only permanent chrome
  • summoned chrome is hostile to the *checking* half of the job
  • app navigation vanishes — “back to work” depends on finding the bar
final · the blend
  • C's page + A's bar + B's vocabulary and panels
  • outline and details are off by default, so the measure is never spent for you
  • claims count in the bar; claims list one labelled move away
  • editing happens in place; the original opens as an overlay
  • one more control than A — the bar carries six actions, all labelled

mindhow the arrangement answers it

Languagesource · source type · provenance · extracted claims · Queue for processing · INBOX/EXTRACTING/EXTRACTED/ARCHIVED · revisions · original document
Decisionreading is never blocked by chrome; the claims count is in the bar before the question is asked; the queue action changes into its own state instead of vanishing; the status *change* lives in Details so the pill can stay a pill
Emotiona source reads like a document, not a database row; extraction is narrated neutrally, so a thin chapter is not a failure; progress and claims answer “how is this going?” without a spinner or a percentage
