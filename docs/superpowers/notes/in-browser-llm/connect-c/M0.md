## What changed

- **Sheet** (`components/ChatSheet.tsx`). `DriveExplorer` renders it over the content column. It is `position: absolute` inside a `relative` column. It was not clipped (panel bottom = viewport bottom), so no portal was needed. A portal to `body` would also lose the `--bai-*` theme variables, which live on the vault's `data-bai-theme` wrapper.
  - Collapsed, it is a pill: the tag, "Ask or change…", and the shortcut label.
  - Expanded, it is a ~45vh panel with a handle, the tag, a History menu (status, Clear, shortcut rebinding) and an Esc button.
  - The panel stays mounted while collapsed.
  - It is centered, so it stays clear of upstream Connect's bottom-right FAB.
- **Hotkey** (`chat/ui/hotkey.ts`). ⌘J on macOS and Ctrl+Shift+Space elsewhere, rebindable (`bai.chat.hotkey` in localStorage). A capture-phase `window` listener matches on `KeyboardEvent.code`.
  - The binding opens the sheet. If the sheet is open but focus is elsewhere, it moves focus into the sheet. If focus is already in the sheet, it collapses it.
  - Esc collapses only from inside the sheet and returns focus to where it was. The New dialog is rendered outside the sheet, so its own Esc handler still works.
- **Tag** (`ChatTargetTag.tsx`, `hooks/use-chat-context.ts`). It reads `useSelectedDocumentId` + `useDocumentSafe` (no suspense) and the file nodes. With a document open it reads "Acting on: *title* (*type*)"; with no document open it shows the drive name. The frame type is `chat/context/context-frame.ts` (`ContextFrame`, `ChatContextProvider`).
- **Targeting** (`chat/core/target-document.ts`).
  - Exactly one *other* supported document named verbatim, and no pointer at the open document: retarget to it (the card says so).
  - Exactly one other supported document named verbatim, and the request also points at the open document ("this", "this note/doc/one/MOC/…", "it", "here"): **ask** which document to change, before the models run (`68b7c000`). Which one changes depends on the intent: "link this note to *X*" is ADD_LINK on the open note, "add this to *X*" changes *X* with the open note as the ref. The choice card (the generalized `ChatChoiceCard`) offers "Change *open title*" and "Change *named title*", each with its type, plus "Neither". The models then run on the chosen document, and the other one stays a ref candidate: the named one ranks by its name, and the open one is pinned with `driveRefContext`'s `keepIds`, so the cap cannot drop it. Choosing the named document shows the amber switch box on the card.
  - Document names are masked before the pointer check, so a title like "Make it work" does not count. "this *item*" ("this goal") does not count either.
  - With nothing open, a pointer has no referent: a title match targets the named document. When the open document's type has no operations, only the named one can change, so a pointer plus a name retargets without asking.
  - A name that only appears inside a longer mentioned name, including the viewed document's own title, does not count.
  - **A non-verbatim mention asks with the top 3** (`071eb3a1`). When no other document is named verbatim but a phrase refers to one by type and an inexact name ("the CRDT MOC" for a MOC titled "CRDTs"), the chat asks which document is meant before the models run. The choice card ("Which document did you mean?") offers the top 3 matches, ranked by lexical score, then recency, then title; then the open document when its type has ops; then "None of these". The chosen one becomes the target. A match chosen keeps the open document as a pinned ref candidate (`keepIds`) and shows the switch box; the open document chosen keeps the matches pinned.
    - A mention is "the", "my", "our" or "that", up to four name words and a type noun ("the CRDT MOC", "my beehive project", "the koji humidity one"), or "the *noun* called/named/titled/about/on *name*". The noun must fit the document's type: note, MOC/map/map of content, project, plan/WBS, observation, tension, claim, derivation, source; doc/document/page/file/one fit any type. Not "a note" ("this one is basically a permanent note now") and not "this note" (the pointer).
    - The type noun and qualifiers ("same", "other", "first", …) are dropped before scoring, so "the honey harvest plan" does not match "Hive plan" on "plan".
    - When the open document fits the phrase at least as well as any other ("tag the CRDT note" on "CRDT merge semantics"), the chat stays on the open document.
    - The verbatim rules run first. At drive level, or on an open document without ops, the card offers only the matches.
  - **Several names, or two documents sharing the named title: the open document.** This follows the powerhouse-nl overview §5.1 Q1 ("Several names, or two documents sharing the name: the open document. … Otherwise ask with the top-3 picker"), which is the resolved decision. **Conflict:** the vault plan §3.2 ("Missing") and §3.9 asked for the top 3 "when several documents are named" as well. The overview wins, so several names do not ask; the plan text is corrected. The retarget dev set (`spike/llm-harness/eval/retarget-dev.README.md`, "Q1 as gold, and one conflict") records the same conflict: on 4 of its 9 several-name and shared-name items, keeping the open document changes the wrong one.
  - Otherwise the action goes to the viewed document.
  - On an unsupported document, the chat says the type has no operations.
  - With nothing open, questions are answered. Other requests get "drive-level changes are not supported yet". A create request also gets a "New *type*" button that opens `CreateDocumentDialog`.
- **Cards** (`CardTarget`). Each card shows "On: *title* (*type*)" from its own target, which is fixed at creation.
  - A retarget gets an amber "Switched target … not the document you were viewing, *B*" box.
  - Once the user navigates away, the card says "You are now viewing *X*. Confirm still changes *A*."
  - Confirm dispatches to `card.target.id`.
- **Session and history.**
  - `chat/context/chat-session.ts` is a module store per drive: the thread, the pending card and the recent ring. It survives a collapse and re-renders.
  - `chat/context/history-store.ts` is IndexedDB `bai-chat-history`/`threads`, keyed by drive id. It caps at 200 entries and 20 recent documents, queues writes, and falls back to memory (the menu then says "not saved").
  - Each entry stores its target, and user entries also store the tag at send time.
  - The pipeline is still single-turn: nothing from history reaches a prompt.
- **Scale fix.**
  - The chat no longer receives document state. The target is loaded by id at send time (`useGetDocument`), and a project's linked plan is loaded by id for its goals.
  - `driveRefContext` builds candidates from node names and known titles (recent ring, open document; a stale node name is kept as an alias). Each kind keeps at most 10, ranked lexically and then by recency, plus the items the target already refers to, so their labels stay.
  - `DriveExplorer`'s project badge now loads only the `bai/project` documents (`useDocumentsByIds`). `DriveExplorer` and the chat no longer call `useDocumentsInSelectedDrive`; other vault views still do.
- **Removed**: the Chat tab, the target `<select>` and the `documents` prop.

## Not done, deviations, limitations

- **Retarget versus ref arguments: fixed in `2a2f967b`, then changed to an ask in `68b7c000`.** "Link this note to *Other note*", said while viewing a note, used to retarget *to* Other note, because its title appeared verbatim. `2a2f967b` made a pointer at the open document block the retarget. That was right for "link this note to *X*" but wrong for "add this to *X*", where the change belongs on *X*. Target resolution runs before the models, so it cannot know the intent: a pointer plus one name now asks which document to change. Unit-tested (pointer + name → ask, both directions keep the other document as a ref; name only → retarget; ambiguous → open document; open document without ops → retarget; drive level → title match), and checked in Connect in the final pass. What the rule still leaves open (training rows and extractors for retargets are M2b/M3 work):
  - every pointer-plus-name request asks, including the ones whose intent is clear ("link this note to *X*"); how often the ask fires is to be measured on the retarget dev set;
  - a pronoun after a name ("add a question to *X* and tag it") also asks, even when "it" means *X*;
  - with nothing open, "link it to *X*" still targets *X*;
  - several named documents, or two sharing a name, act on the tag, as overview Q1 says (see "Targeting" for the conflict with the vault plan).
- **Q1 rule differences found with the retarget dev set** (resolution only, in rules this pass did not change; for the M2b work, not fixed here):
  - a sentence-initial "This *verb*" is not read as a pointer ("This contradicts *X*.", "This builds on *X*.", "How is this different from *X*?"), so it retargets where the gold asks which of the two (rt-pn-03, rt-pn-14, rt-na-04);
  - when the open document shares its title with another document, the other one counts as named, so the chat retargets where Q1 keeps the open document (rt-sn-03, rt-sn-04);
  - a name that also occurs inside the open document's title is dropped even where it also stands on its own ("CRDTs should list Delta CRDTs Cut Bandwidth …" while viewing "Delta CRDTs Cut Bandwidth"), so the chat keeps the open document where the gold switches (rt-sw-09);
  - ordinal items (rt-or-*) need the vault context store;
  - a non-verbatim mention with no determiner or type noun does not ask (rt-nm-07, rt-dl-05).
- **The top-3 rule's limits.** The match is lexical (shared words and shared prefixes of four or more letters), so a mention by meaning only ("the beekeeping project" for "Rooftop beehives") does not ask; server semantic candidates (§3.9) would cover it. The type nouns are hand-listed for the vault's types (M2 can generate them from the manifest).
- **Pending cards are not restored after a reload.** A live card holds the catalog entry (zod, creators), which cannot be cloned into IndexedDB. The thread keeps a "Proposed X on A (waiting for Confirm)" line instead. Navigation and collapsing keep the live card.
- **Not in this M0 pass (plan §3.4/3.6/3.7):**
  - the vault context store (graph focus, search results, visible ids), and with it deictic and ordinal resolution (`resolveOrdinal` returns undefined);
  - server semantic candidates;
  - the ~60-item retarget dev set (written later by a separate writer, `b95abdb2`).
- **No drag-resize on narrow screens.** The handle only collapses.
- **Firefox ⌘J `preventDefault` [unverified]:** Firefox was not tested (not runnable here). The Ctrl+Shift+Space default was checked only with the platform reported as Windows on macOS, not on a Windows or Linux machine.
- **Version drift.** `package.json` pins 6.2.2-dev.47, but `node_modules/@powerhousedao/*` links a local monorepo at 6.2.3-dev.78. The hooks used here (`useDocumentSafe`, `useDocumentsByIds`, `useGetDocument`) were checked in that build. The pnpm reinstall (`d2950ef4`) moved the install to the registry 6.2.2-dev.47, but Studio on that install fails to start (final pass, setup), so the hooks are still unchecked there.
